# 전자 입고확인서 MVP

종이 영수증이나 사진 첨부 없이 `전자 입고확인서 작성 -> 문자앱 열기 -> 전송 완료 표시 -> 밤 정산 집계` 흐름을 검토하기 위한 정적 프론트엔드 프로토타입입니다. 백엔드, DB, 로그인, 실제 문자 API, 카카오톡 API, OCR, 사진 첨부는 구현하지 않습니다.

## 실행 방법

1. `confirm-app/index.html`을 브라우저에서 엽니다.
2. 별도 빌드나 서버가 필요 없습니다.
3. 확인서 데이터는 브라우저 `localStorage`의 `haebaramConfirmAppV1` 키에 저장됩니다.
4. 상단의 `샘플 초기화` 버튼으로 샘플 데이터를 다시 만들 수 있습니다.

## GitHub Pages 검토 경로

GitHub Pages가 저장소 루트를 정적 사이트로 배포하도록 설정되어 있으면 `confirm-app/index.html`은 아래 경로로 접근합니다.

- 루트 도메인 기준: `/confirm-app/`
- GitHub 프로젝트 페이지 예시: `https://<owner>.github.io/<repo>/confirm-app/`

Pages 설정에서 배포 소스가 저장소 루트가 아니라 별도 폴더라면, 위 경로는 그 배포 루트 기준으로 다시 확인해야 합니다.

## 기존 receiving-app과의 차이

- `receiving-app`: 영수증/사진 기반 입고 입력, 농가별 정산/입금 대상 흐름 검토.
- `confirm-app`: 전자 입고확인서 작성, 문자앱 열기, 사용자의 전송 완료 표시, 밤 정산 집계 흐름 검토.
- `confirm-app`에는 단가표 관리 UI가 없습니다. 내부 Mock 단가표로만 자동 계산합니다.

## 가족 검토용 체크리스트

1. `/confirm-app/`에 접속해 첫 화면이 열리는지 확인합니다.
2. `새 입고확인서 작성`에서 농가명, 전화번호, 품목/등급/용기, 수량을 입력합니다.
3. `확인서 미리보기`에서 NO, 농가명, 상세 줄, 정산 반영 합계, 단가 미정 건수를 확인합니다.
4. `문자앱 열기`를 눌렀을 때 휴대폰 문자앱으로 넘어가는지 확인합니다.
5. 문자앱 본문이 비거나 기기에서 링크가 다르게 동작하면 `문구 복사`를 눌러 직접 붙여넣습니다.
6. 실제 문자는 사용자가 문자앱에서 직접 전송합니다.
7. 전송 후 웹앱으로 돌아와 `전송 완료로 표시`를 누릅니다.
8. `밤 정산 대상` 화면에서 농가별 집계와 단가 미정 건수를 확인합니다.

## 문자앱 열기 방식의 한계

- `[문자앱 열기]`는 `sms:` 링크로 기기 문자앱을 여는 방식입니다.
- 브라우저와 기기마다 `sms:` 링크의 동작과 본문 자동 입력 지원이 다를 수 있습니다.
- 웹앱은 실제 문자 전송 성공 여부를 알 수 없고, 사용자가 문자앱에서 직접 전송해야 합니다.
- 그래서 `[문구 복사]` 버튼을 fallback으로 제공하고, 전송 후 사용자가 `[전송 완료로 표시]`를 눌러 상태를 바꿉니다.

## 전화번호 저장 정책

- 전화번호 전체는 `localStorage`에 저장하지 않습니다.
- 작성 중에는 문자앱 링크 생성에만 사용합니다.
- 저장 데이터에는 표시용 `phoneLast4`만 남깁니다.
- 저장된 확인서를 나중에 다시 열면 전화번호 전체가 없으므로 문자앱 링크를 재생성할 수 없습니다. 저장된 문구 복사와 전송 완료 표시만 제공합니다.

## 단가와 정산

- 내부 Mock 단가표에 있는 조합은 자동으로 `unitPrice`와 `amount`를 계산합니다.
- 단가표에 없는 조합은 `단가 미정 / 정산 확인 필요`로 표시합니다.
- 단가 미정 줄은 정산 반영 합계와 밤 정산 CSV 지급 합계에서 제외하고, 단가 미정 건수로 별도 표시합니다.

## 향후 백엔드/SMS API 연결 항목

- 서버 저장소와 확인서 ID 채번.
- 농가 마스터와 전화번호 권한 관리.
- SMS API 발송 요청, 발송 성공/실패 콜백, 재발송 이력.
- 확인서 상태 변경 감사로그.
- 단가표 마스터와 정산 확정 절차.
- 개인정보 보관 기간, 접근 권한, 마스킹 정책.
